# Google Apps Script 保存用

このフォルダは、現行GASのバージョン管理用コピーを保持します。GitHubからApps Scriptへの自動デプロイは行わないため、変更後は実運用のApps Scriptプロジェクトへ手動で反映します。

- Web API: `code.gs`
- 返却行: `artist / title / kind / dText / dUrl / date8 / rowId`
- `date8`: D列先頭8文字 (`YYYYMMDD`) の投稿日
- `rowId`: `artist|title|kind|dUrl`（同一曲の複数履歴を URL 差分込みで識別）
- 検索: `exact=1` 指定時は `artist/title` 完全一致を優先

- 実運用統合スクリプト: `merge-songs-gags-archive.gs`（仕分け／統計／動画監査／統合一覧）

## 楽曲仕分けの確定仕様

処理キーの「同一楽曲」は、A列アーティスト名とB列曲名の組み合わせです。

### 歌った曲リスト

1. 同一楽曲の重複グループだけを処理し、重複のない行は所属と並び順を変えません。
2. A列＋B列＋D列URLが完全一致する行は1件にします。D列表示文言やC列区分は完全重複キーに含めず、URLが空の行は削除しません。
3. A列＋B列＋C列区分＋D列先頭8文字の `YYYYMMDD` が一致し、URLだけが異なる場合は、新しく追加されたURLを残します。
4. 残った同一楽曲は `歌ってみた > 歌枠 > ショート` の順で1件を残します。同一区分は投稿日が新しい行を残し、それ以外をアーカイブへ移動します。

### アーカイブ

1. 同一楽曲の重複グループに対し、完全重複の削除と同日・同区分の再アップロード置換を行います。
2. 区分優先度による1件化は行わず、アーカイブからメインへの復帰も行いません。
3. メインから移動した行を加えた後に再整理するため、移動先で生じる重複も除去します。

### 日常用処理と新しく追加された行の判定

- 日常用仕分けでは、新規行の有無にかかわらず毎回両シート全件のA列＋B列重複を検査します。
- Document Propertiesの前回メイン最終行は処理対象の絞り込みには使わず、それより下に追記された行を新規データとして優先するためだけに使います。
- 同じ実行で複数候補が新規の場合は、下の行をより新しいものとします。
- 総点検では過去の追加時刻を復元できないため、同一シートの下の行を新しいものとする決定的な代替判定を使います。
- 初回も「重複を仕分け（日常用）」を単独で実行できます。チェックポイントがない初回は全メイン行を新規候補として扱い、同一条件では下の行を優先します。

書換え直前にはメインとアーカイブの非表示バックアップを作り、直近5世代を保持します。
